# PR29 状态优先级与构建来源修复（2026-11-17）

> 可信度更正（2026-11-17）：本页历史 strict 回放的 execution_valid=true 声明已撤回。日志重判分数保留，但 build ID 不能认证原采集的实际内核、磁盘、QEMU 和 argv。当前回放标为 REPLAY_UNVERIFIED，退出 1；原文件与哈希保留供审计。

针对 91032a6 的两条 unresolved，根因属于跨阶段设计边界，不能仅补两个条件分支。

## 为什么前几轮仍有遗漏

前几轮主要围绕已报告的触发条件补负例，缺少跨阶段的统一约束。段解析、judge、全局 capture 错误各自改写状态，修复一条覆盖路径后仍可能被另一条覆盖。构建器又把共享输出的当前字节当作本次输入的派生物，哈希只能证明输出自洽，不能证明来自本次 APK。旧测试中有一项主动改写解包输出后期待新构建 ID，验证了内容绑定，却错误接受了来源污染。

本轮将该测试改为修改真实 APK 输入，并明确拒绝外来输出。保留已稳定的清单、判据和证据回放；重写状态归并与构建数据交接。测试数量不是无缺陷证明。

## 约束与修复

| 阶段 | 约束 |
| --- | --- |
| 状态归并 | 一处优先级表：明确环境/来源/协议错误 > capture 超时或段 EOF 截断 > 其他协议不完整 > LOG_ERROR > CAPTURE_ERROR > 判分与脚本状态。非零 capture 不能覆盖截断段 TIMEOUT，退出码留在元数据。 |
| strict 协议 | 区分合法前缀未完成与非法协议。前者可在截断/超时场景保留 TIMEOUT；错误构建 ID、非法顺序、REF_FAIL 仍失效。未完成协议不会成为有效通过。 |
| APK 解包 | 同一字节快照校验 APK SHA256，再解出不可变 kernel/module 字节。身份、cpio 内容、输出哈希均从这些字节生成，不回读共享 Image/modules 作为来源。 |
| 输入消费 | 源码/配置/输入保留路径绑定及 inode/大小/mtime/ctime/模式；BusyBox 还核对实际打开的文件描述符，读取前后复查。短暂换别名再恢复或改写再恢复原字节/时间不能冒充稳定输入。 |
| 发布 | 私有临时文件完整写入后，以原子硬链接创建目标；同内容可复用，不同内容拒绝覆盖。产物校验后最后创建 manifest，失败不发布新 manifest。 |

发布是逐文件原子创建，不声称跨文件回滚。发生竞争后可能留下没有 manifest 的部分组件；不同输入/选择/源码版本请使用独立输出目录。构建器不会覆盖已有不同内容来强行完成。

## 验证

新增负例先在旧实现出现 11 个失败断言；后续同类检查又复现 4 个 strict 前缀分类失败、2 个输入恢复/文件描述符失败、3 个空输入入口失败。状态测试含真实子进程非零退出、混合完整/截断组、环境/日志/超时/judge/脚本组合；空采集命令或空日志参数在执行前退出 2。

并发测试用管道控制两个独立构建进程的顺序，不靠睡眠碰运气。分别覆盖冻结/实验构建先发布，以及内核不同、仅模块不同两种 APK；赢家产物必须全部来自其 APK，另一方明确失败且不发布新 manifest。另用线程屏障验证原子创建竞争：同内容可复用，同长度异内容不能覆盖赢家。

`make check mm-smoke irq-smoke` 通过 110 项专项、52 Rust、15 原有 Python 及 BOOT-001/MM-002/ARCH-001。最后扩展的同长度发布竞争用例也单独通过。15 份历史状态、逐项判分和数量不变，仍为 13 份完全一致、2 份已登记诊断增补。

实际冻结输入完成最终构建；原路径重复构建时 14 个产物的字节、inode、mtime 均不变。最终代码真实 QEMU 采集 Lua glibc 9/9，同一日志回放 musl 9/9；4 GiB 镜像两次执行仍各完整哈希 2 次。本轮另有一次中间版本的参考启动验证，留存最终版本的一次启动证据，未重跑完整 22 次测量。

原始串口、实际 manifest 和采集/回放摘要见 lua/；实现、测试及证据 SHA256 见 [validation.json](validation.json)。旧证据与 Release 不覆盖，结果仍不计为 FocOS/真板成绩。

原始 serial.log 已转存外部固定哈希归档；本目录摘要与 validation 的原始哈希保留。下载位置、逐文件路径与校验值统一见 [原始证据索引](../../raw-evidence-2026-11-17.json)。库内不再保存含上游版权邮箱的日志，旧判分和原始字节不修改。
