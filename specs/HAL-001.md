# HAL-001：块设备接口与内存盘

关联：Issue #1

## 要做到什么

对于底层不同硬件，让上层通过统一接口按块读写数据，先用内存盘验证正常读写和错误行为。

## 行为约定

- 块大小固定为 512 字节；设备提供总块数 N，有效块编号为 0..N。
- 每次读取或写入一个完整块，调用者提供恰好 512 字节的缓冲区。
- 写入第 0 块后，再读取第 0 块，应得到相同数据；其他块不受影响。
- 缓冲区长度不等于 512 字节，返回缓冲区长度错误。
- 块编号大于或等于 N，返回越界错误。
- 实现遇到上述参数错误时，不修改盘内数据，也不修改调用者缓冲区；
  真实后端须在访问硬件前完成校验，使被拒操作不产生任何设备与介质访问。
  设备读写失败（`Io`）不承诺缓冲区或目标块完整。共享契约测试按本条
  拒收参数错误后改动缓冲区或数据的实现。
- 底层设备读写失败时，接口向调用者返回错误。
- 内存盘由调用者独占使用，本步不处理并发访问。
- 内存盘借用调用者的缓冲区，保留原有内容；长度必须是 512 的整数倍，否则返回 `InvalidCapacity`。允许空盘，总块数为 0，任何块编号均越界；借用结束后调用者重新使用原缓冲区。
- 参数校验先检查缓冲区长度，再检查块编号；对应 `InvalidBufferLength` 和 `OutOfBounds`，巨大块编号不得因偏移计算溢出而访问其他数据。
- `flush` 表示请求同步此前写入；内存盘直接成功，
  只保证数据仍在内存中，不提供断电持久化保证。
- 底层设备不支持同步时，`flush` 返回不支持错误；同步失败时返回设备错误。
- Rust 接口为 `BlockDevice`：`block_count(&self) -> u64`、`read_block(&mut self, block: u64, buffer: &mut [u8])`、`write_block(&mut self, block: u64, buffer: &[u8])` 和 `flush(&mut self)`。后三者返回 `Result<(), BlockError>`；`Io` 表示设备错误，`Unsupported` 表示能力不支持，默认 `flush` 返回 `Unsupported`。
- 硬件 I/O 失败不承诺传输原子性；调用者不能把失败操作视为已完成。内存盘参数错误的数据不变保证仍按上文执行。

## 怎样验收

以下均为开发机（host）测试，统一入口为 `make test`；契约检查及其非合规设备负例见 `kernel/src/block/contract/`，内存盘的契约薄壳与专属断言见 `kernel/src/block/memory/tests.rs`。故障设备仅验证接口错误可见性，不作为真实驱动或断电持久化证据。

| 场景 | 操作或测试入口 | 应看到什么 |
|---|---|---|
| 正常读写 | 写入第 0 块后读回；使用不同字节组成的数据 | 内容一致，其他块不变，字节顺序不变 |
| 最后一块 | 读写第 N−1 块 | 成功 |
| 越界 | 访问第 N 块和 `u64::MAX` | 返回越界错误，数据不变 |
| 长度错误 | 使用 0、511 或 513 字节缓冲区；同时提供非法块编号 | 返回长度错误，数据不变；长度错误优先 |
| 容量与借用 | 尝试非整块容量、空盘和已有数据；释放内存盘后检查原缓冲区 | 非整块容量报错；空盘无有效块；构造保留内容，释放不擦除写入 |
| 设备失败 | 使用可注入读写失败的测试设备 | 错误传递给调用者 |
| 内存盘同步 | 写入后调用 flush，再读回 | 成功且内容一致；不代表断电保存 |
| 不支持同步（unsupported-sync） | 使用不覆盖默认 `flush` 的测试设备，经统一块设备接口调用 `flush` | 调用者收到不支持错误；不得返回成功 |
| 同步失败（failed-sync） | 向支持同步的测试设备写入数据，注入同步故障，再经统一块设备接口调用 `flush`；清除故障后重试 | 调用者收到设备错误；不得吞掉错误或返回成功；重试成功且数据仍在 |

测试先失败再实现。标明 host / QEMU / 真板；证据放 PR，不在这里重复维护运行状态。

## 与平台接入的关系

本规格定义设备无关的块接口，内存盘是其 host 验证实现。真实设备按 [DRV-001](DRV-001.md) 接入，由 [PLAT-001](PLAT-001.md) 提供资源并装配；MMIO、DMA、IRQ 不进入本接口或文件系统。HAL-001 编号沿用，不能将它当作全部 CPU/板级 HAL 的规格。
