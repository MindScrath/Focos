# MM-002：在 QEMU 中使用真实物理页

关联：[Issue #4](https://github.com/MindScrath/Focos/issues/4) · 范围：QEMU 单核

## 要做到什么

让内核从可用内存初始化 MM-001 页分配器，完成实际页的写入、读回、释放和再次分配。本步只验证 QEMU，不含真板接入、堆分配、页表、用户映射和 `mmap`。

例：内核末尾为 `0x8021f123`、设备树起址为 `0x87e00000` 时，只分配 `[0x80220000, 0x87e00000)` 中的完整页。

## 行为约定

- **启动范围**：首个验收环境为 QEMU 8.2.2 / OpenSBI 1.3.1，沿用 BOOT-001 的 RISC-V `virt`、`-m 128M -smp 1 -bios default`，不传自定义设备树、初始内存盘或额外内存镜像。物理内存（RAM）为 `[0x80000000, 0x88000000)`；单核、关闭中断和分页时执行。平台常量及启动参数处理放在 HAL/arch；本约定不用于 VisionFive2 的 `bootelf` 入口。
- **可分配范围**：入口保留 `a1` 中的设备树（DTB，硬件描述数据）起址。链接符号 `__kernel_end` 位于全部内核装载段之后，包含未初始化数据、启动栈和分配标记。起点为 `__kernel_end` 向上按 4096 字节对齐，终点为 DTB 起址向下按页对齐。只把这段左闭右开区间交给 `PageAllocator::new`；低端固件与内核、DTB 所在页到 RAM 末尾、RAM 外的设备地址均不参与分配。本步不解析设备树内容。
- **布局错误**：先检查 `0x80200000 <= __kernel_end < dtb_start < 0x88000000`、DTB 起址按 8 字节对齐，再检查对齐运算及结果。地址无效、运算溢出或没有完整可用页时返回 `InvalidLayout`；不初始化分配器，不修改标记或待分配页。
- **初始化与所有权**：在报告启动成功前初始化一次。标记使用内核静态存储，不从待分配页或堆中申请；容量不足按 MM-001 返回 `MetadataTooSmall`，不静默缩小范围。启动流程独占分配器；分配、耗尽和非法释放沿用 MM-001，失败不改变已有状态。
- **实际访问**：调用者只访问仍持有的已分配页，释放前结束所有引用；释放后不得继续使用旧地址。物理地址转指针的 `unsafe` 必须说明范围、独占和有效期。分配器仍不访问或清零页内容；自检使用不会被编译器省略的整页读写，不依赖初始内容。
- **启动结果**：自检完成并归还测试页后，输出一次 `FOCOS_MM_OK`，再按 BOOT-001 输出启动标记并正常关机。初始化失败或读回不符时报告原因，走 `FOCOS_PANIC` 与失败关机路径，不输出成功标记。专项检查同时核对两个唯一成功标记、退出状态及超时，不能只检查打印内容。

## 怎样验收

host 指开发机测试，统一运行 `make test`；QEMU 专项入口为 `make mm-smoke`。

| 场景 | 操作或测试入口 | 应看到什么 |
| --- | --- | --- |
| 范围与保留区 | host：[布局测试](../kernel/src/arch/riscv64/memory/tests.rs)，覆盖上述例子及未按页对齐的 DTB 起址 | 两端正确对齐；可分配区不与保留区相交 |
| 布局与初始化失败 | host：DTB 为零、越界或未按 8 字节对齐；内核越界、对齐后无完整页；标记不足 | 返回 `InvalidLayout` 或 `MetadataTooSmall`，标记和页内容不变 |
| 真实读写与回收 | QEMU：`make mm-smoke`；两页写不同图样并逐字节读回，释放一页再申请、写读新图样 | 两页地址不同；仍持有的另一页内容不变；最终归还全部测试页后才报成功 |
| 错误判定 | [检查器负向测试](../scripts/test_smoke.py)：旧内核只有启动标记；缺失/重复标记、panic、非零退出或超时 | 均判失败，不把 BOOT-001 通过当成 MM-002 通过 |
| 原有行为回归 | `make check` | MM-001、HAL-001 的开发机测试及 BOOT-001 仍通过；耗尽和非法释放行为不变 |

先让专项检查因缺少内存行为失败，再实现到通过。PR 保存源码 SHA、QEMU/OpenSBI 版本、命令、实际分配范围和日志；QEMU 结果不作为真板验收。
