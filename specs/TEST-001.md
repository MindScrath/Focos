# TEST-001：运行官方测试并保留原始输出

关联：[Issue #8](https://github.com/MindScrath/Focos/issues/8) · 状态：草案，待人工审阅；宿主入口已实现，客体执行待联调。

## 要做到什么

让队友能够构建 FocOS、挂载固定版本的 2025 初赛镜像并查看完整输出。目标仍是 RISC-V musl/glibc 的原 11 组及比赛冻结版本 LTP 全部通过；本规格先交付运行入口，不实现日志解析、通过率或自研判分。

## 行为约定

- 宿主入口：`python3 scripts/official_test.py --image /绝对路径/sdcard-rv.img --out target/official/run-001 --timeout 3600`。先校验参数、镜像哈希和新输出目录，再调用 `make build` 构建当前 FocOS，按官方 RISC-V 启动参数挂载镜像；参数取值与版本见[依据](../docs/reference/official-test-entry.md)。不把参考 Linux 当作默认内核。
- 使用固定镜像的原始程序和脚本。宿主入口负责启动 QEMU；内核负责扫描、串行运行两套 libc 的测试脚本并关机。不得把上游 `test_all.sh` 当成全量入口，它未启用 LTP。当前内核只支持 128 MiB 布局，官方 1G 配置会 panic；该依赖及用户态能力未就绪必须在运行说明中明示，不自动改成较小内存或通过扫描日志推断兼容状态。
- 在客体内以对应的 `/musl` 或 `/glibc` 为工作目录，按脚本要求提供 shell、子脚本解释器和 ELF 所需的动态加载器与库。启动出错时保留原始诊断和脚本路径。每组结束后回收该组留下的后台服务及后代，确认资源释放后再启动下一组。清理失败时停止后续组，记录中止位置。
- 每次使用全新的输出目录，保存实际命令、内核/镜像 SHA-256、工具版本、构建日志、原始串口日志及运行结束原因；已有目录直接拒绝。运行时同步显示串口输出。串口内容不删改、不去重，不从中计算总通过结论。
- 复制输入镜像到本次私有输出目录，校验副本并从该只读副本启动；使用 QEMU 临时写入层供文件测试使用，运行结束后丢弃。启动失败、超时、用户中断和日志写入失败均停止本次运行，回收本次 QEMU 及其子进程；已有日志保留，清理失败明确报错。
- 退出 0 只表示构建成功且 QEMU 进程返回 0，不保证内核未 panic；参数、缺失输入或镜像校验错误退出 2，构建/启动/运行/写入/清理失败退出 1，超时退出 124，Ctrl-C 退出 130，SIGTERM 退出 143。`--timeout` 为启动 QEMU 后的正整数秒数，不含构建；中断也须停止构建子进程。停止时先请求终止，最多等待 5 秒后强制回收；清理失败优先退出 1，同时保留原始结束原因，不覆盖旧证据。
- 判分暂不纳入入口：官方 BusyBox 脚本与 judge 仍有版本对应问题，见 [Issue #48](https://github.com/MindScrath/Focos/issues/48)。确认匹配后原样接入官方工具，结果另存；不得修改命令表或判据来消除差异。未确认前只提供原始输出，不宣称全套通过。

## 宿主怎样确认“无残留”

入口以独立的单线程进程运行，一次启动一个外部命令。每次结束前须回收命令本身及它创建的所有宿主后代，包括另建进程组或会话的后台程序。只有确认内核已无子进程，才能启动下一条命令或报告本次结果。命令开始前已有子进程时拒绝启动，避免误清理。客体内各测试组的后台服务由客体另行回收。

支持普通用户运行的 Linux 主机和容器，要求能接管孤儿进程、观察和终止本次后代。若内核没有提供 procfs 的 `children` 文件，入口通过同一 PID 命名空间的 `/proc` 查找进程。无需 root、可写 cgroup 或特定的 checkpoint/restore 内核配置。宿主拒绝所需操作、无法确认后代已回收时，停止后续命令并返回 1，输出目录可写时在 `run.json` 保留原始结束原因和清理错误。保证覆盖入口能处理的退出路径；入口自身遭 SIGKILL 或主机断电时无法执行清理。

QEMU 主进程结束后，保存退出码和管道中已缓冲的串口内容，然后清理后代。后台程序继续持有串口写端时，同样按此顺序结束。复跑方法见[宿主进程验收](../docs/reference/official-test-entry.md#宿主进程验收)。

## 宿主环境和结束记录

- **源码归属。** 源码采样与构建使用同一个 FocOS 工作树。入口从脚本所在的仓库根目录发现 Git 仓库，兼容普通 clone 和 linked worktree。调用方用于选择其他仓库、索引、对象库或改写查询结果的 Git 环境设置不传入源码查询和构建。
- **构建条件。** 入口为版本查询和 `make build` 构造同一份环境。保留运行工具所需的路径、工具链目录与临时目录等宿主设置。允许的编译器、Rust 编译标志和 release 参数继续传入，按实际值记入 `run.json`。其他调用方提供的 Git、Make、Cargo、Rust 构建覆盖默认不传入。本阶段目标链接器由仓库配置与所选工具链决定，忽略宿主的 `CARGO_TARGET_RISCV64GC_UNKNOWN_NONE_ELF_LINKER`。运行记录描述入口显式支持的环境覆盖；完整复现系统工具和用户配置文件不在此约定内。
- **结束记录。** 输出目录创建后，入口负责记录一次运行的结果。运行期间收到 SIGINT 或 SIGTERM 时先清理子进程；从运行切换到写记录期间收到的信号也要保留。收尾期间的信号只更新待记录原因，不打断写文件。入口首次写出记录并报告原因后，屏蔽信号并读取待处理集合，以此作为收尾截止点；截止前收到的中断反映在记录和进程退出码中，清理失败仍优先返回 1。目录不可写时报告写入失败并返回 1。

队友可按以下场景验收实现：

| 操作 | 应看到什么 |
| --- | --- |
| 在另一个仓库导出 Git 仓库和工作树变量，从 FocOS 的 linked worktree 启动入口；先用干净工作树，再修改其中一个源码文件 | 两次都记录 FocOS 提交，只有第二次记录本地修改 |
| 将目标链接器变量指向一旦执行即报错的脚本，同时设置一个受支持的 release 参数 | 正常构建，脚本未执行；release 参数按实际值记入记录 |
| 分别在开始收尾、写运行记录期间发送 SIGTERM，并另测清理失败 | 输出目录可写时没有异常堆栈，记录与进程退出码一致；普通中断为 143，清理失败为 1 并保留两种原因 |

## 怎样验收

| 场景 | 操作 | 应看到什么 |
| --- | --- | --- |
| 当前 FocOS | 上述命令 | 保留实际启动输出、版本与退出码。当前基线在 1G 下 panic，未来内核修复后以新日志为准 |
| 组间清理 | 顺序执行 musl、glibc 的 iperf | 前组后台服务器已退出，后一组能在客体内重新绑定 5001 端口；清理失败时保留日志并停止 |
| 完整兼容验收 | 内核具备依赖后运行全部官方脚本 | 两套 libc 全范围原始输出，按对应官方标准确认；入口交付不能关闭兼容性目标 |
| 错误输入/重复目录 | 错误镜像或重用 OUT | 拒绝启动，不改已有文件 |
| 超时/中断/日志写失败 | 挂起的 QEMU、Ctrl-C、不可写目标 | 非零退出、保留已写日志、无本次残留进程 |
| 脚本内部失败但外层退出 0 | 参考 Linux 中缺少脚本解释器 | 失败文本原样保留，入口不报告测试通过 |
| 镜像隔离 | 在测试中写文件后退出并再次运行 | 基础镜像哈希不变，下次没有上次写入 |

**Issue #8 的关闭条件**：队友能从文档准备依赖，通过仓库入口在 FocOS 上实际运行两套 libc 各 12 组原始脚本（含 LTP），复查原始输出、运行条件及异常清理证据，并能依据已核实的官方工具或标准判断结果。缺组、未能启动脚本或判据待核实，接入验收仍未完成。已执行测例暴露的内核兼容失败由对应模块跟踪，附原始日志。全部通过另按 [REGION-001](REGION-001.md) 验收。
