# TEST-001：可追溯的测试采集与判分

关联：[Issue #8](https://github.com/MindScrath/Focos/issues/8) · 状态：第三轮规格草案，待非作者审阅

## 要做到什么

接入 2025 初赛原 11 组与比赛冻结版本 LTP，分别报告参考 Linux 校准和 FocOS 验收。一次采集允许用新判据另存重判报告。本轮替代 #29/#46 的实现路线，只交付规格；没有新 runner 或兼容成绩。

## 行为约定

- **入口**：`build / capture / analyze / campaign` 分期交付。A 只提供 `analyze --log SERIAL --profile P --criteria J --libc musl --group lua --out NEW`；`--run` 到 C 才开放，未交付入口退出 2，不能凭手工运行包提前取得验收 PASS。
- **唯一判分路径**：私有原始字节 → 记录 → 按组/调用状态归属 → 规范结果 → 验收。结果、性能指标、诊断共用同一个解析结果。旧 judge 的分数单独列为对照，不能与另一条记录的 proof 拼出 PASS；禁止下游重新扫描正文或整段批量标记已消费。
- **范围**：PROFILE 冻结真实调用、参数、顺序与分片，CRITERIA 独立冻结语法、判据、实现及兼容映射。调用身份不等于 judge 输出名称；计划中的同名重复有独立 ID。每个观察调用必须属于当前 selection；PROFILE 中已知但范围外的调用也阻断验收，不扩大分母或填补缺项。未知、遗漏、重试和跳过不缩小分母；动态断言另计。观察调用序列须与 PROFILE 对当前 selection 冻结的序列逐项一致，不能排序或去重后比较。未审计闭合的组不能标为完整冻结。
- **错误**：保留采集、输入完整性、协议、调用结果及验收各自的状态。缺结束、重复、非法/孤立结构和跨组输出均保留原位置并阻断；后来的成功不能清除早先错误。LTP 的失败、跳过、警告和测试异常不冒充判分器故障，原生结果与汇总不重复计数。
- **可信度与所有权**：外部日志固定 `external_log/unknown`，验收始终 BLOCKED。各阶段只消费已校验私有快照，只写独占新目录；完整清单最后发布。采集退出 0、日志 PASS、参考 Linux 校准均不能单独证明 FocOS 通过。
- **退出与限额**：输入/未支持接口为 2，执行或发布失败为 1；普通分析发布完整报告为 0，`--require-pass` 在 BLOCKED 时为 1。限额在读取/执行期间生效。输入错误、发布失败或工具自身无法完成阶段时，不发布可消费的完成清单；采集超时、输出超限或非零退出时，若仍能完整发布，则保留含原始串口和失败状态的运行包，capture 退出 1，后续分析验收为 BLOCKED。完整规则见[阶段契约](../docs/reference/test001-redesign.md)。

## 怎样验收

| 场景 | 待实现入口 | 必须看到 |
| --- | --- | --- |
| 规范正例及缺项 | 纯解析测试、A 外部日志 CLI | 正例逐项 PASS；缺项 MISSING；两者验收均 BLOCKED |
| ANSI 合法结果 + NBSP 重复结果 | A CLI；C 完整运行包 | 不同记录不能拼成成功，重复/非法结构有原位置 |
| TPASS 后孤立 `failed: 999` 再接合法 Summary | 同上 | 孤立字段立即报错，后续 Summary 不清除错误 |
| 截断、失败后成功、未知/跨组输出 | 同上 | 全部原因保留，分母不变，验收不升为 PASS |
| 采集失败与发布失败 | C，分别注入超时/超限/非零退出及写入失败 | 前者在发布可完成时保留完整失败运行包，capture 退出 1、验收 BLOCKED；后者无可消费完成清单 |
| 已知但范围外调用 | 选择 LTP 分片 S1，插入同 PROFILE 的 S2 调用 | 成功/失败/未结束均 OUT_OF_SELECTION、BLOCKED；分母不变，范围内缺项不被填补 |
| 冻结调用顺序 | 同一分片的相邻调用对调，即使全部成功 | ORDER_MISMATCH、BLOCKED；保留原始观察顺序和差异位置，不改分母 |
| 旧包重判 | C，P1 配 J1/J2 | 原日志/采集身份/分母不变，报告另存 |
| 完整批次 | D campaign | 采集前冻结全范围，每槽一次，失败/缺槽不能用成功重跑替换 |
