# ARCH-001：隔离 CPU 机制与架构 ABI

关联：[Issue #4](https://github.com/MindScrath/Focos/issues/4)、[#5](https://github.com/MindScrath/Focos/issues/5)、[#11](https://github.com/MindScrath/Focos/issues/11) · 状态：本核临界区已实现（待审阅）；页表、上下文与用户 ABI 仍待专项 SPEC

## 要做到什么

让公共内核通过统一接口使用 CPU 能力，切换 RISC-V / LoongArch 时复用内存、调度和文件系统逻辑。本规格确定边界；页表、上下文等具体操作须在实现前补充专项 SPEC。

## 行为约定

- **选择**：编译时选择架构实现，对外统一导出；CPU 寄存器、页表项、架构汇编和架构相关 ABI 布局只在架构实现中出现。HAL 提供稳定入口，避免公共模块直接引用 `arch/riscv64` 等具体模块。
- **内存**：公共内存模块拥有物理页和映射生命周期；架构层负责页表操作、权限转换和 TLB 失效。接口必须约定对齐、失败后的映射状态、TLB 完成时机；不支持的权限组合明确报错，不能放宽权限。物理地址、内核虚拟地址和设备 DMA 地址须可区分。
- **执行**：架构层保存/恢复上下文，将异常转换成公共事件；调度、阻塞和退出由公共内核决定。用户上下文、浮点状态、系统调用参数/返回值、TLS 与信号布局须逐架构核对；ELF 机器类型不匹配时拒绝加载。
- **时钟与中断**：统一时间单位和单调性；临界区接口保存并恢复调用前的本核中断状态，允许嵌套；它只屏蔽本核可屏蔽中断，不提供跨核互斥。外部中断控制器由驱动实现，板级层提供连接与频率；定时事件交公共调度逻辑处理。
- **接口落地**：每项专项 SPEC 写清签名、调用前提、所有权、并发/unsafe 条件及失败状态。初期单核要求显式标注；增加 SMP 前补跨核 TLB、上下文和同步约定，不能宣称已有多核支持。

## 第一份实现

先实现 `with_local_irqs_disabled<R>(f: impl FnOnce() -> R) -> R`：保存本核状态并关中断，执行一次 `f`，正常返回时恢复原状态并返回 `f` 的结果。屏蔽/恢复边界须阻止编译器将受保护访存移出临界区，但不代替设备或跨核内存屏障。嵌套按调用栈恢复；闭包中禁止阻塞、调度、跨核迁移或自行修改中断状态。内核 panic 的终止路径不承诺恢复后继续运行。

先写下表的状态测试，再接架构指令。后续页表/上下文各自拆专项 SPEC；不要在同一任务中实现全部架构接口。RISC-V 的状态自检、编译器屏障审阅与 QEMU 证据见[实现参考页](../docs/reference/local-irq-critical-section.md)；真实定时中断专项见 [ARCH-002](ARCH-002.md)，本分支实现仍待两名成员审阅。

启动自检 `unsafe fn check_local_irq_state() -> Result<(), IrqCheckError>` 会主动切换 SIE。调用方必须保证启动流程独占当前 hart，整个调用期间 `sie` 始终为 0；仅关闭 SIE 的运行期临界区不满足前提。无论返回成功或错误，SIE 均为 0；入口 SIE 为 1 时清零并返回 `InitialStateEnabled`。HAL 与架构层导出均保留 `unsafe` 要求，`make test` 用真实 RISC-V 库编译调用方：普通调用报 E0133，显式 `unsafe` 调用可编译。

## 怎样验收

下列是验收门槛；本 PR 已新增 RISC-V 本核临界区的 `make irq-smoke` 状态自检，真实屏蔽另由 `make irq-timer-smoke` 验证；其他能力仍待对应实现。

| 场景 | 操作或测试入口 | 应看到什么 |
| --- | --- | --- |
| 抽象边界 | 审阅依赖和架构选择；构建各已接入目标 | 公共模块不引用具体架构；不支持的目标明确失败 |
| 临界区状态 | 每个已接入架构的 QEMU 专项：RISC-V 已提供 `make irq-smoke`，分别从开/关中断进入单层和两层闭包，读取 CPU 状态并核对调用次数/返回值；其他架构待实现 | 初态开：外层关 → 内层关 → 退出内层仍关 → 退出外层开；初态关：全程及最终仍关；单层退出恢复原态，闭包只执行一次且结果透传 |
| 编译器屏障 | 实现 PR 必须静态审阅关中断 → 闭包、闭包 → 恢复中断两处边界，记录所用编译器访存约束及依据；同时审查仅有 `asm!(…, options(nomem))` 且无其他编译器屏障的负例；RISC-V 审阅记录见[参考页](../docs/reference/local-irq-critical-section.md) | 两处均能阻止受保护访存移出临界区；负例必须判失败。寄存器/定时器测试通过不能替代此审阅，CPU 屏障指令也须核对其编译器语义 |
| 临界区实际屏蔽 | QEMU：外层临界区内制造待处理定时中断，用计数器记录执行时间（`make irq-timer-smoke`，接口与验收见 [ARCH-002](ARCH-002.md)） | 外层退出前处理器计数不变；原态开则恢复后收到中断，原态关则显式开启后才收到 |
| 页表与隔离 | 各架构 QEMU 专项测试（待实现） | 映射/撤销及权限生效；失败无残留；非法用户访问受控 |
| 上下文与时钟 | 各架构 QEMU 专项测试（待实现） | 任务切换后寄存器正确，定时器持续触发，时间不倒退 |
| 用户 ABI | 各架构最小 ELF、系统调用、TLS/信号测试（待实现） | 参数与返回值正确；错误架构 ELF 被拒绝 |

配套边界见 [PLAT-001](PLAT-001.md)、[DRV-001](DRV-001.md)；临界区首步可先于设备驱动实现。总体边界见 [架构](../docs/architecture.md)。涉及 HAL、ABI 与内存安全，需另外两名成员审阅。
