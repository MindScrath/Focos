# MM-001：物理页分配与回收

关联：[Issue #4](https://github.com/MindScrath/Focos/issues/4) · 状态：已实现（待队友审阅）

## 要做到什么

管理一段可用物理内存，支持按页分配、释放和复用，检测内存耗尽及非法释放。本次只实现可在开发机测试的分配逻辑，不包含真实内存接入、堆分配、页表、用户映射和 `mmap`。

## 行为约定

- **管理范围**：页大小固定为 4096 字节。初始化传入字节地址范围 `[start, end)`，两端必须按页对齐且 `start <= end`；总页数为 `(end - start) / 4096`。允许空范围。
- **初始化**：`PageAllocator::new(start: usize, end: usize, used: &mut [bool]) -> Result<Self, PageAllocError>`。调用者提供每页一个标记的存储，长度至少为总页数；成功后将所需标记设为空闲，多余标记不变。范围错误返回 `InvalidRange`，标记空间不足返回 `MetadataTooSmall`；先检查范围，再检查容量，失败不修改标记。分配器独占借用标记存储，不依赖堆分配。
- **分配**：`alloc(&mut self) -> Result<usize, PageAllocError>` 每次返回一页的起始物理地址。结果必须位于管理范围内、按页对齐，且不能重复分出尚未释放的页。不约定分配顺序；无空闲页时返回 `OutOfMemory`，已有状态不变。
- **释放**：`dealloc(&mut self, addr: usize) -> Result<(), PageAllocError>` 只接受本分配器中当前已分配的页首地址。不对齐或范围外地址返回 `InvalidAddress`；合法范围内的空闲页再次释放返回 `NotAllocated`。先校验地址，再检查分配状态；失败不改变状态。
- **所有权**：调用者负责在该页不再被使用后，向原分配器显式归还；归还后不得继续使用旧地址。当前状态检查不识别旧地址被重新分配后的历史持有者，本步不提供引用计数或自动回收。
- **访问边界**：分配器只管理地址和标记，不解引用物理地址，不读写或清零页内容。后续接入内核时，由调用者排除内核、固件、设备及管理信息等保留区域，确保不同分配器不重复管理同一页；交给用户程序前的清零由后续映射层负责。当前通过 `&mut self` 串行操作，不提供全局共享或并发支持。

例：管理 `[0x1000, 0x4000)` 时，连续三次分配得到三个不同页首地址，第四次返回 `OutOfMemory`；释放其中一页后，再分配应成功。

## 怎样验收

本阶段使用开发机（host）单元测试，统一入口为 `make test`，用例见 [kernel/src/mm/tests.rs](../kernel/src/mm/tests.rs)。测试中的地址只作数值使用，不访问对应物理内存。

| 场景 | 操作或测试入口 | 应看到什么 |
| --- | --- | --- |
| 正常分配 | 分配三页范围内的全部页 | 地址均对齐、在范围内且互不重复 |
| 耗尽与复用 | 分完后继续申请，再释放一页并申请 | 耗尽明确报错；释放后可用；不影响仍被占用的页 |
| 重复及未分配释放 | 连续释放同一页；释放从未分配的页 | 返回 `NotAllocated`，不增加可重复分配的资源 |
| 非法地址 | 释放不对齐地址、范围外地址及 `end` | 返回 `InvalidAddress`，原分配状态不变 |
| 初始化失败 | 反向范围、不对齐边界、标记空间不足 | 返回对应错误，标记存储不变 |
| 空范围与单页 | 空范围申请；单页反复分配和回收 | 空范围返回耗尽；单页可反复复用，无泄漏 |
| 重复运行 | 多轮分配全部页并全部释放 | 每轮容量一致，无重复分配或资源丢失 |

测试先因缺失行为失败，再实现到通过；提交时运行相关测试和 `make check`，证据放 PR。开发机通过不代表 QEMU 或真板内存接入通过。
