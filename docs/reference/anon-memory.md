# MM-005 参考：匿名映射与堆顶

## 接口与返回值

[MM-005](../../specs/MM-005.md) 在公共内存层为每个用户地址空间管理一个区间 `[base, limit)`。调用方选取已排除程序段、栈和保护页预留的区间。两端须按页对齐、`base < limit`，区间须完全位于本空间用户范围内且没有既有映射。违反任一条件返回 `InvalidLayout`，原空间仍可用。原页表本身损坏时传播 MM-004 的 `InvalidTable`。初始堆顶为 `base`，没有堆页。

下表省略共用的地址空间、页分配服务和架构参数。各入口返回 `Result<T, VmError>`，箭头后为成功值 `T`。

| 入口 | 成功行为 |
| --- | --- |
| `mmap_anon(len: usize, perm: MapPerm) → VirtAddr` | 返回能够容纳所需页数的最高页对齐起点。整段虚拟地址连续，各物理页可以不相邻。`perm` 接受 `USER_R`（用户只读）或 `USER_RW`（用户读写），两者都不可执行 |
| `munmap_anon(start: VirtAddr, len: usize) → ()` | `len` 向上取整到页，撤销从 `start` 起覆盖的所有匿名页。允许跨多段映射，也允许全为空洞。先校验完整区间，再修改页表与映射记录 |
| `brk(end: Option<VirtAddr>) → VirtAddr` | `None` 查询，`Some(end)` 设置。`base <= end <= limit`，成功设置后堆页覆盖 `[base, align_up(end))`，权限为 `USER_RW`。`align_up` 向上取到页边界。同一尾页内缩小再增长保留原页，硬件仍按整页授权。整页归还后再次分配须重新清零 |
| `destroy() → ()` | 显式销毁非活动用户空间。归还本层剩余的匿名页、堆页，并由 MM-004 归还私有页表。活动空间返回 `ActiveAddressSpace`，已销毁空间再次调用任一入口返回 `Destroyed` |

初始化后的入口先检查对象状态，再检查长度、地址及对齐，然后检查权限和区间，最后申请资源。长度取整和地址相加均检查溢出。以下错误均保留调用前的映射、内容、堆顶和可用资源。`InvalidLength` 与 `NoVirtualSpace` 为本规格拟增的 `VmError` 值。

| 输入或失败点 | 返回错误 |
| --- | --- |
| 映射或撤销的长度为零，或长度向上取整溢出 | `InvalidLength` |
| 虚拟地址不能由架构表示，或撤销起点加取整长度溢出 | `InvalidAddress` |
| 撤销起点未按页对齐，或申请了不支持的权限 | 分别为 `UnalignedAddress`、`UnsupportedPermissions` |
| 撤销范围超出管理区或涉及任一堆页，或请求的堆顶超出 `[base, limit]` | `ProtectedMapping` |
| 找不到足够长的连续空闲区，或增长后的堆页会覆盖匿名映射 | `NoVirtualSpace` |
| 数据页、下级页表页或记录容量耗尽（含撤销中段需要额外记录时） | `Allocator(OutOfMemory)`。整段回收与销毁无需额外申请页或记录 |

## 页由谁归还

公共内存层持有 `VmMemory::alloc_zeroed_page` 返回的独占句柄，复用 MM-004 的 `map_page`、`unmap_page` 和受控拷贝。沿用单核、关中断、无内核堆的前提。管理对象独占用户空间的修改权。若向调用方提供逐页映射或撤销入口，目标在管理区内时须返回 `ProtectedMapping`，防止绕过页句柄记录。发布映射前结束对物理页的可变借用，撤销前结束对目标页的访问。[MM-004 接口与资源](user-mapping.md#接口与资源)

跨页申请或扩堆中途失败时，撤销本次已发布的映射，归还新数据页、空表页和记录。活动树上的旧转换须在复用任何页之前失效。销毁前确认 CPU 未使用该根，数据页归还给原页服务。管理区外的数据页与共享内核表页继续由原持有者管理。若原分配器拒收合法句柄，保留句柄并按既有所有权故障终止启动。[MM-003 安全前提](sv39-paging.md#错误与安全前提)

## 验收用例

开发机用 `make test` 验证以下行为，先保留失败用例，再实现相应入口。

- 用写过非零图样的回收页申请 4097 字节，检查两整页。依次让跨页申请和扩堆的每个数据页、页表页申请点失败，比较旧映射的地址、权限、内容、堆顶及两类页数。
- 初始化拒绝未对齐、越界或含既有映射的区间，且零分配。在单页管理区将堆顶从 `base + 1` 调到 `base + 2` 再退回，页数与首字节不变。堆顶恰好等于 `limit` 时仍占一页，缩至 `base` 后堆页数为零。
- 有足够零散空页、没有连续两页时，申请两页应返回 `NoVirtualSpace`。逐项覆盖上表的错误，包括记录耗尽。一次撤销多段匿名映射及其间空洞应成功，混入堆页或越界时整次拒绝。
- 验证调用方无法绕过管理对象逐页修改区内映射。两个空间在同一虚拟地址写入不同内容，销毁其中一个后另一个仍可读回。拒绝活动销毁，重复销毁返回 `Destroyed`。管理区外另映射一张外部持有的页，销毁空间后由原持有者读回并归还。

QEMU 使用 4 KiB 页。以下区间 `[0x20000, 0x28000)` 仅用于自检，由调用方传入。创建用户空间前记录数据页数、表页数和原页服务的占用总数。用 MM-004 的 `copy_to_user` 和 `copy_from_user` 实际读写活动空间，对失败的单字节拷贝核对读或写页故障、故障地址和 `copied = 0`。

1. 申请三页读写匿名内存，起点应为 `0x25000`。核对初始零值，再分别写入不同图样。撤销 `0x26000` 起的 1 字节，原先访问过的中间页应在首字节报页故障，另两页仍能读回原图样。对同一空洞再撤销一次应成功。申请一页只读内存应复用 `0x26000`，读回全零，写入非零字节报错且内容仍为零。
2. 设置堆顶为 `0x21001`，在两张堆页的首字节分别写入不同非零值并读回。收缩到 `0x21000` 后，第一页保留原值，地址 `0x21000` 再读报页故障。再增至 `0x25000` 应成功，新分出的页读回全零。请求 `0x25001` 应返回 `NoVirtualSpace`，查询仍得 `0x25000`，相邻映射内容不变。
3. 切回内核根后直接销毁仍有映射的用户空间。两类页计数以及原页服务的占用总数均须回到各自基线。检查器核对地址、实际拷贝结果、故障地址和回收计数，拒绝旧内核、缺失、重复或乱序记录、意外异常、非零退出与超时。

匿名映射交付先验收步骤 1、3。堆管理交付使用同一专项依次验收步骤 1–3。实现 PR 运行 `make check`、`make mm-smoke`、`make irq-smoke`、`make vm-smoke`、`make user-vm-smoke` 和 `make anon-vm-smoke`，保留源码版本、内核 ELF 哈希、环境、命令与原始日志。
