# TEST-001：词法输入完整性重设计（待审）

暂停 [PR #56](https://github.com/MindScrath/Focos/pull/56) 的实现修补，先审定本页。既有“唯一词法→归属→规范结果”架构保留；本次重新定义整个词法阶段内部的处理顺序及中间表示，防止正常化掩盖输入损坏。设计审定后重做词法实现，再处理未解决评审，不以补测试或协议最终 BLOCKED 代替正确的记录事实。

## 为什么暂停

[新评审](https://github.com/MindScrath/Focos/pull/56#discussion_r4626106165)已实测复现：`b'\xc2\x1b[31m\xa9testcase lua date.lua success\n'` 的原始 UTF-8 非法，但当前实现先删颜色再解码，得到合法的 `©testcase ...` 并当作普通信息。四字节字符也有同类问题。它与原本合法的 `©testcase ...` 在正常化后不可区分；下游再加前缀规则已无法恢复丢失的事实。

前两轮分别补了“拒绝控制字符”和“损坏前缀仍保留开始事件”，但仍建立在这个会修复字节的表示之上。根因是正常化顺序和错误分支的输入表示没有统一约束。本轮禁止继续对显示字符串增加跳过/strip 特判。

## 整体数据流

```text
原始 bytes
  → 仅按 LF 分 RawRecord（固定原字节区间）
  → 按原始字节边界生成 Unicode/坏字节 Unit
  → 在 Unit 上一次生成完整 Token 流（先识别控制字符串的外层）
  → 校验完整性，并选择合法结构识别或损坏结构分类
  → 一个 LexRecord（原字节/映射/分类/保留前缀事实）
  → 既有组/调用归属状态机 → 不可变规范结果
```

两种分类分支属于同一个词法入口，不是两套判分器；它们共用 Unit/Token，互斥地产生一个 LexRecord。归属、判分和渲染均不重新解释原始字节、转义显示文本或整段正文。

### 1. 原字节与 Unit

- 仍仅按 LF 分记录。原记录包含原换行；识别视图只排除终止 LF 及紧邻它的一个 CR。裸 CR 留在输入中报错。
- **在移除任何 SGR/控制内容之前确定 UTF-8 完整性。** 严格按原始 UTF-8 边界解码，不允许过长编码、代理码点、越界码点或不完整序列。SGR 的 ASCII 字节也是原输入的一部分，不能先删除再“接续”多字节字符。
- 每个 Unit 是一个合法 Unicode 标量及其原始半开字节区间，或一个不可解码的原始字节。一个坏字节不能借后续颜色之外的 continuation byte 变成合法字符。允许一次使用 surrogateescape 保留不可解码字节，但必须把它们转成独立坏字节 Unit，不能当 Unicode 字符、普通文本或 `ignore` 处理；禁止 surrogatepass。
- Unit 区间按原顺序恰好覆盖识别视图，互不重叠。显示用 `\xNN` 只是渲染，不是前缀检测或结构匹配的输入。

### 2. Token 与控制内容

Token 只引用连续 Unit 区间，完整覆盖 Unit 流；每个 Unit 恰好归一个 Token。Token 包括普通文本、允许的 SGR、拒绝的控制序列、拒绝的控制字符、坏字节及不透明控制字符串。

- 允许 SGR 仍只有 ESC[0m、ESC[31m、ESC[32m、ESC[33m、ESC[39m，且必须是完整、顶层控制序列。合法识别视图只能省略这些 Token，不能省略任意字节。
- CSI 使用已登记的参数/中间字节/终止字节结构；除上述五种 SGR，其余 CSI 均拒绝。拒绝不意味着内容从原记录丢弃。
- OSC 先作为完整外层字符串识别：支持 ESC ] 或 U+009D 开始，BEL、ESC + 0x5c 或 U+009C 结束。其消息体不透明，即使包含看似 SGR 或 testcase 的文本也不递归解释；不透明不豁免其原始 UTF-8 校验。未闭合 OSC 保留到本条物理记录结束并拒绝，不跨 LF 拼接。
- 未登记的转义入口及无法确定边界的控制字符串作为未知控制段保留到本记录结束；不扫描其内部猜调用。当前不实现通用终端模拟器。
- Unicode 控制/格式字符沿用源码固定的 Unicode 16.0 Cc/Cf 集合（ASCII HT 例外）；不得用不同 Python 的运行时 Unicode 分类改变协议。其他非 ASCII 空白也不能作为合法字段分隔。

### 3. 校验后才能选择分类分支

**完整输入分支：** 原记录的 UTF-8 完整，Token 中无拒绝项。此时才可省略允许的顶层 SGR，生成带原始字节映射的识别文本，并完整单行匹配已登记结构。颜色可以穿插 ASCII 文本，但不能跨原始非法 UTF-8 边界修复字符。完整匹配失败但命中保留前缀时，仍从同一 Token 流进入损坏结构分类出口，不重新解码或 token 化。普通可打印 Unicode 诊断仍可为信息。

**损坏分支：** 任一坏字节、拒绝控制或其他非法结构永久保留错误，禁止运行能产出合法结果的匹配路径。只在同一 Token 流上判断是否有已登记的损坏结构开始：

1. 从记录开头出发，仅越过空白、允许 SGR、已登记的拒绝控制前缀和坏字节 Token。
2. 仅当随后直接出现保留前缀 testcase，标记未知调用开始。遇到普通文字立即停止；不进入 OSC/未知控制段的消息体搜索。
3. 输出 INVALID_STRUCTURE 与未知身份的观察，并保留 ORDER_UNVERIFIABLE。name/status/group/libc 不从显示文本或 selection 补造；不构成任何合法调用尝试。
4. 无调用保留前缀时仍保留非法记录及错误，但不虚构调用。这里覆盖的是显式登记的损坏前缀语言，不承诺从任意乱码/未知终端语言推断原本意图。

原始合法 `©testcase ...` 是普通文本前缀，不能凭包含 testcase 而制造观察。原始非法 `C2 + SGR + A9 + testcase ...` 则是坏字节/颜色/坏字节前缀，必须留下未知开始；二者不能先正常化为同一个字符串再分类。

## 对既有状态机的影响

- `analyze_lua` 的外部参数、固定 selection 投影和不可变结果边界不扩张。不借此次重设计开放其他组、PROFILE、CLI 或运行包。
- RawRecord、Unit、Token 和 LexRecord 的位置映射保留完整链路；合法结果和损坏开始均来自同一个 LexRecord，错误记录仍有唯一归属。
- 未知开始进入 observed_sequence，不能被过滤成空序列或合法前缀；它不能填补所选调用，所选项仍可为 MISSING。原样错误与未知观察同时保留。
- 顺序诊断仍独立于合法单次 PASS/FAIL；重复失败事实、范围检查及严格前缀规则不退回。外部验收固定 BLOCKED。
- 最终引用检查只验证对象区间、角色和唯一归属；不能为“证明成功”再扫描原文。

## 审定后必须先失败的验收矩阵

| 原始输入/变换 | 必须看到 |
| --- | --- |
| 两套真实 Lua 样本、LF/CRLF、五种允许 SGR | 合法单次结果、顺序和原字节映射不变 |
| 合法 ©/三字节/四字节字符后接 testcase 文本 | 普通信息，不造观察 |
| 在同一字符的每个内部字节边界插入每一种允许 SGR | UTF-8 错误；不得恢复为合法字符/信息；若后接保留前缀则有未知观察 |
| 单字节坏前缀、不完整 UTF-8、过长编码、编码的代理码点、越界编码 | 保留坏字节、位置及错误；不使用替换/忽略结果作结构输入 |
| 只在合法码点边界插入允许 SGR | 不损坏原 UTF-8；合法结构与 Unicode 诊断按各自语法分类 |
| 合法结果后追加上述损坏开始 | 合法观察及未知观察都保留；协议 ERROR，不能静默去掉第二条 |
| TINFO/普通消息/完整及未闭合 OSC 内引用 testcase、颜色串 | 消息不递归解释；错误/信息按外层处理，不造调用 |
| 错组/组外/范围外/重复/重排与损坏记录组合 | 原状态机事实保留，身份未知的事件不重绑为所选项 |
| 原字节→Unit→Token→识别映射 | 区间连续覆盖、无重叠/遗漏；原字节可复原，渲染不能改变身份 |

变异至少包括：先删 SGR 再解码、UTF-8 ignore/replace 后分类、从显示转义文本识别前缀、在 OSC 内删除颜色或扫描 testcase、丢弃未知开始。每项必须由独立手写期望击中，并保留合法正例；现有顺序/首次失败/保留结构变异继续执行。Python 3.11 与系统 Python 均须检查相同规范结果，不只比较 acceptance=BLOCKED。
