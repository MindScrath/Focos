## 2026 年 11 月 5 日 VisionFive2 首次上板准备

用户认领 #2，亲自完成串口接线、记录固件启动及 U-Boot 查询；Codex 读取本地日志，查阅 U-Boot v2021.10 和赛昉分支的 bootelf/ELF 加载实现，草拟 BOARD-001、上板指南、独立构建选项和入口改动。bootelf 的 argc/argv 与 Linux 的 hart/DTB 入口分别处理；输出借用 SBI，尚未实现 UART 驱动、输入或定时中断。

验证：新增模拟调用检查先对现有内核运行，因只输出 BOOT-001 标记且退出而预期失败；实现后回归 `make check`，并用 `make vf2-check` 在 QEMU 模拟 argc=0/2。该检查不运行真实 U-Boot 或 JH7110；FocOS 真板输出、队友冷启动复现和人工审阅仍待完成。完整日志保留在本地 target/evidence，不公开原始设备标识或登录信息。实际测试结果以本次执行日志及后续板上记录为准。

另依据 v2021.10 的 ELF loader 发现其不筛选程序头类型；先验证默认 ELF 被兼容性检查拒绝，再用显式 PHDRS 限制为 PT_LOAD，并加入段边界与文件范围检查。该实现由 Codex 草拟，涉及启动 ABI 和链接布局，仍需另外两名成员人工审阅。

验证中还发现 Cargo 未追踪通过 rustflags 引用的链接脚本；增加 build.rs 的 rerun-if-changed 声明，使链接布局修改能触发实际重新链接。

首次真板验证：用户将板卡 SD 插入读卡器，Codex 核实设备及 FAT 分区后复制已测试的 ELF，验证哈希和原有文件内容未变，完成卸载；用户装回卡并通过串口执行 U-Boot 命令。2026-11-05 日志记录 22720 字节装载成功、`Starting application at 0x80200000`、版本和 `FOCOS_VF2_BOOT_OK`。Codex 冻结原始日志并整理去除设备标识的 docs/evidence/BOARD-001-20261105.txt，更新 README、规格和指南的实测范围。该记录绑定 ELF 和未提交源码快照哈希；UART 驱动、定时中断、队友独立复现及人工审阅尚未完成。早前会话有 SD 响应超时，未归因，不能由本次成功推断稳定性。

提交准备：按用户要求提交并发布首次启动步骤以供队友查看和复现，CI 增加 RISC-V binutils 与 `make vf2-check`。公开内容仅含代码、指南和去除设备标识的实测节选，原始日志、完整本地快照和 devdoc 不进入提交。代码合入和队友冷启动验收仍由人工完成。

代码已归档为 `3e536a444387c1d383dea7a21c505189cb1e94b3`；指南给出固定提交的 clone/checkout 步骤，使队友在 main 合入前也能准确复现。本次提交基于上手文档 PR #14，新 PR 需注明这一依赖，不能把继承的文档提交误认为本次新增工作。
