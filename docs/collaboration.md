# 从认领到合入：六步 SOP

一次 PR 交付一个能验证的行为。模块可以大，第一次交付尽量控制在 3–6 小时。

| 步骤 | 作者做什么 | 队友确认什么 |
| --- | --- | --- |
| 1 认领 | Issue 设 Assignee，写下一步、预计时间、reviewer | 没有人重复实现，依赖有人接 |
| 2 约定 | 复制 [SPEC 模板](../specs/TEMPLATE.md)，写输入、错误与验收 | 使用接口的人先审；通过后再实现 |
| 3 写测试 | 让测试因缺失行为失败，保留原因 | 失败不是故意破坏编译 |
| 4 实现 | 写到测试通过，再重构、回归 | 不放宽断言、不伪造成功 |
| 5 提 PR | 填 [PR 模板](../.github/pull_request_template.md)，附准确 SPEC 与证据 | 行为、规格、命令和提交对应 |
| 6 合入 | 审阅通过后 squash，更新 Issue | 未完成整项验收时保持 Issue 开放 |

小缺陷可在同一 PR 更新 SPEC、失败测试和修复，但行为改变仍先审约定。纯文档检查事实、链接和可读性，不补无关代码测试。

## 认领与分支

从最新 `upstream/main` 建 `spec/编号-主题`、`feat/编号-主题` 或 `fix/编号-主题`，推到个人 fork。操作命令见 [上手指南](getting-started.md)。一人同时一个实现任务；每周 30 分钟合流演示。

Assignee 是模块 owner；reviewer 与下一步写在 Issue 顶部。owner 维护依赖、SPEC/PR/结果链接，卡住一天就找队友，超过两天拆小或结对。待认领表由 [开放 Issue](https://github.com/MindScrath/Focos/issues) 自动反映，文档不再复制一张进度表。

## 测哪些层

| 改动 | 必要证据 |
| --- | --- |
| 解析、分配、路径、缓存 | host 单元测试：正常、边界、故障注入 |
| 异常、进程、syscall、程序兼容 | QEMU 集成：真实程序、退出状态、超时与副作用 |
| HAL、驱动、内存/DMA、持久化 | 对应提交的板上冒烟；发布前独立冷启动复现 |
| 性能 | 固定条件配对实验、原始数据、绘图脚本 |

当前 CI 门禁是 `bootstrap`：格式、Clippy、host 测试、构建、BOOT-001 与 MM-002 真实页检查。兼容测试和新增平台检查随模块接入；先运行并稳定，再单独提 PR 加入必过集合。已纳入的测试失败阻断合并，不能静默移除。共享 CI 计时仅作烟测；板卡 runner 只运行维护者确认的提交并独占设备。

## 谁批准

普通 PR：一名有写权限的非作者。HAL、ABI、内存安全、持久化：另外两名成员都审。检查失败路径和资源释放，AI review 提供建议，不替代批准。

GitHub 当前强制 `bootstrap`、跟上 main、至少一人批准、推送后重新批准、解决讨论及禁止强推/删除 main；仅允许 squash。两人审阅靠团队额外执行。配置快照见 [main-protection.json](../.github/main-protection.json)，文件不会自行修改服务器。

新增、移动、删除路径或改变用途，同一 PR 更新 README 文件树。reviewer 对照 Files changed 核对。main 回归先恢复可构建状态，再定位原因。

## 性能回归与记录

性能 PR 记录 base/head SHA、设备/镜像、预算、负载、命令、7 轮配对原始数据及差异。吞吐下降 >5% 或 p95 上升 >10% 且超过噪声时复测并登记 Issue；这是初始预警线，需用实际基线校准。功能或持久化错误直接阻断合入。

小数据与脚本入库，大日志放 artifact 并为候选版另行归档。每项结果都能追到提交；凭据、个人报名资料和 devdoc 不上传。来源与 AI 使用记在 [ai-usage.md](ai-usage.md)。
